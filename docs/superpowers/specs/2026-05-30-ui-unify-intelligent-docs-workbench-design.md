# 前端 UI 统一为智能文档三栏工作台设计

日期：2026-05-30  
范围：`apps/web` 整个前端站点  
视觉基准：`apps/web/src/pages/intelligent-docs.astro` 与 `apps/web/src/styles/intelligent-docs.css`

## 1. 目标

将整个前端站点统一成当前“智能文档”页面的产品感觉：浅绿白背景、硬边框大工作台、三栏信息架构、清晰的依据优先表达。首页不再保留多套割裂的卡片堆叠风格，而是重构为与智能文档同款的三栏工作台。

本次目标包括：

- 首页与智能文档页像同一个产品。
- 首页采用“左侧 Workspace / 中间主任务 / 右侧 Evidence”的三栏工作台结构。
- 统一顶部导航、移动端快捷导航、按钮、输入框、提示、卡片、折叠依据、状态信息的视觉语言。
- 保留现有核心功能入口：跑者画像、计划生成、训练日历、今日训练、依据、反馈、历史计划、高级设置。
- 先交付可运行样板页面，让用户查看整体感觉，再继续细节打磨。

## 2. 非目标

- 不重写后端 API。
- 不改变训练计划生成、画像存储、日历渲染、反馈提交等业务逻辑。
- 不引入新的 UI 框架或设计依赖。
- 不在本轮解决多用户隔离、权限、云端部署等后端生产问题。
- 不删除现有功能，只改变信息组织和视觉承载方式。

## 3. 设计方向

采用“智能文档同款三栏工作台”。

### 3.1 页面骨架

全站页面共享以下结构语言：

```text
顶部导航：品牌 / 搜索 / 主导航 / 连接状态
移动端快捷导航：今日 / 计划 / 我的情况 / 依据 / 智能文档
主工作台 shell：深色描边、大圆角、浅色背景、轻阴影
左栏 Workspace：导航、准备步骤、画像摘要、历史/设置入口
中栏 Main：当前任务、输入、计划、日历、当天训练
右栏 Evidence：风险提示、引用依据、规则来源、反馈操作
```

## 4. 组件与样式系统

### 4.1 统一站点外壳

从智能文档页面抽取并复用以下概念：

- `docs-top` 的顶栏视觉成为全站顶栏基准。
- `docs-shell` 的三栏工作台成为首页样板主框架。
- `docs-side` 成为左侧导航/上下文栏基准。
- `docs-main-column` 成为主任务区基准。
- `docs-evidence` 成为右侧依据栏基准。
- `docs-row`、`docs-answer`、`docs-alert` 成为折叠依据、回答卡片、风险提示的样式基准。

实现时可以保留现有 class 名，也可以新增更通用的别名，例如 `app-top`、`app-shell`、`app-side`、`app-main`、`app-evidence`。为了降低一次性改动风险，优先复用当前智能文档样式，并逐步把首页 DOM 映射到这些样式能力。

### 4.2 视觉规则

- 背景：页面底色使用智能文档的浅绿白方向，例如 `#eef5ef`。
- 主 shell：白色或近白色背景，深绿色硬边框，圆角约 `24px`，轻阴影。
- 文本：深绿色/墨色为主，高权重标题，紧凑正文。
- 强调色：沿用智能文档的深绿按钮和绿色状态点，避免新增杂色。
- 控件：输入框、按钮、搜索框、折叠行统一圆角、边框、字重和 hover 反馈。
- 卡片：减少厚重卡片堆叠，优先用工作台分区和细边框区块。

### 4.3 响应式规则

- 桌面端：三栏工作台。
- 中等宽度：左栏变窄或折叠，右侧依据栏可下移。
- 移动端：主 shell 改为单列；导航使用移动端快捷导航；依据区折叠到主内容下方。

## 5. 信息架构

### 5.1 左栏 Workspace / Context

左栏承载“去哪儿”和“当前上下文”：

- 准备：完善跑者资料、快捷模板。
- 查看：训练日历、今日训练、训练依据、智能文档。
- 调整：历史计划、反馈调整、高级设置。
- 摘要：跑者身份卡和连接状态可作为折叠/摘要区呈现。

### 5.2 中栏主任务区

中栏承载用户最常用的操作：

- 顶部标题：例如“生成训练日历，查看今日安排。”
- 计划输入区：保留 prompt、生成按钮和必要画像字段入口。
- 今日训练卡：展示当天训练、强度、原因、风险调整。
- 训练日历：保留现有日历交互能力，视觉上嵌入工作台中栏。
- 反馈区：完成、疲劳、疼痛反馈入口保留，但压缩为主任务后的操作区。

### 5.3 右栏 Evidence / Risk / Actions

右栏强化“依据优先”：

- 风险提示：疼痛、疲劳、负荷突增、连续高强度等。
- 引用依据：训练强度、恢复建议、文档片段、规则来源。
- 快捷操作：补充画像、查看智能文档、重新生成、反馈调整。
- 状态：证据不足、后端连接异常、生成中等状态要清晰显示。

## 6. 数据流与行为

本轮不改变数据流，现有脚本继续负责业务行为：

- `apiClient.js` 继续处理 API 调用。
- `app.js` 继续驱动首页状态、计划生成、画像和交互。
- `calendarRenderer.js` 继续渲染训练日历。
- `intelligentDocs.js` 继续驱动智能文档页面问答和依据折叠。

UI 重构只调整 DOM 容器、class 和样式。若某些脚本依赖具体选择器，实施时必须保留对应 `id`、`data-*` 或添加兼容 wrapper，避免功能断裂。

## 7. 错误处理与空状态

统一使用智能文档风格的轻量提示：

- 后端未连接：顶部状态 pill + 中栏提示，不阻塞浏览静态样板。
- 计划未生成：中栏显示清晰的空状态和生成入口。
- 依据不足：右栏显示证据覆盖不足提示。
- 日历为空：保留生成提示，不显示破碎布局。
- 移动端溢出：内容单列堆叠，避免横向滚动。

## 8. 验收标准

- 首页和智能文档页在视觉上属于同一套设计系统。
- 首页桌面端呈现智能文档同款三栏工作台。
- 首页核心功能入口仍可找到：画像、生成计划、日历、今日训练、依据、反馈、历史计划、高级设置。
- 智能文档页作为视觉基准不退化。
- 移动端可正常浏览，无明显横向溢出。
- 构建通过：`cd apps/web && npm run build`。
- 前端 smoke 通过或明确记录失败原因：`cd apps/web && npm run smoke:workspace`。

## 9. 实施顺序建议

1. 先抽取/复用智能文档的工作台样式能力。
2. 重构首页顶栏与主 shell。
3. 将首页左侧 drawer/导航整理为 Workspace / Context。
4. 将计划输入、今日训练和日历迁移到中栏主任务区。
5. 将依据、风险、反馈快捷操作迁移到右栏。
6. 调整响应式样式。
7. 运行构建和 smoke，修复选择器兼容问题。
8. 交付可运行样板供用户查看。
