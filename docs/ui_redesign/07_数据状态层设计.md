# 数据状态层设计（产品级细化版）

## 1. 文档目的

本文档定义马拉松助手数据状态层的产品级设计。数据状态层负责把用户画像、训练计划、反馈数据转化为用户能理解的训练状态——不是原始数据，而是"可感知的判断"。

## 2. 模块定位

数据状态层是用户了解"我现在状态怎么样"的模块。用户需要知道自己当前恢复是否良好、训练负荷是否合适、本周完成度如何、下次能否继续训练。

## 3. 用户场景

### 3.1 场景 A：每天打开看状态

用户每天打开系统，想知道今天的状态。

困惑：今天适合训练吗？我恢复了吗？本周完成了多少？

### 3.2 场景 B：连续几天感觉很累

用户连续几天觉得累，想知道系统有没有检测到。

困惑：系统知道我最近疲劳吗？训练负荷是不是太高了？

### 3.3 场景 C：刚完成一次高强度训练

用户刚做完间歇跑，想确认自己状态正常。

困惑：这次训练对我的状态有什么影响？明天还能继续吗？

## 4. 信息架构

```text
数据状态面板
├── 本周完成度（进度条：3/4 天完成）
├── 当前训练负荷（负荷水平标签 + 趋势箭头）
├── 恢复状态（良好 / 一般 / 需关注）
├── 风险等级（低 / 中 / 高 + 原因一行）
├── 下次训练建议（日期 + 类型 + 状态依据）
└── 长期趋势入口 → 长期进度层
```

## 5. 组件拆分

### 5.1 状态面板（StatusPanel）

- 位置：入口层状态条区域 或 独立面板
- 类型：CustomElement（React 组件）
- 职责：聚合展示当前训练状态
- 子元素：完成度 Progress、负荷 Badge、恢复 Badge、风险 Badge

### 5.2 本周完成度（WeeklyCompletion）

- 类型：Progress + 分数文本（如 "3/4"）
- 数据来源：本周反馈累计

### 5.3 负荷指示器（LoadStatusBadge）

- 类型：Badge + 趋势箭头
- 展示：当前负荷水平 + 与上周对比

### 5.4 恢复状态标签（RecoveryBadge）

- 类型：Badge
- 展示：良好（绿）/ 一般（黄）/ 需关注（橙）
- 数据来源：反馈中的疲劳 + 睡眠

### 5.5 风险等级标签（RiskLevelBadge）

- 类型：Badge + Tooltip
- 展示：低/中/高 + 原因
- 数据来源：不适反馈 + 疲劳 + 训练负荷 + 周反馈累计

## 6. 交互流程

入口层自动加载 → StatusPanel 展示 → 用户可点击各项跳转详情

## 7. 状态设计

- 有状态数据：正常展示
- 无状态数据（首次使用）：展示引导设定基线
- 数据异常：展示最后已知状态 + "数据更新中"

## 8. 与 Option A 架构的关系

- 数据来源：`state.adaptive_feedback`、`state.workout_feedback` 累计、用户画像
- FastAPI 端点（新增）：`/status/{user_id}` GET

## 9. Chainlit 落地

- CustomElement：StatusPanel
- 文件：`public/elements/StatusPanel.jsx`

## 10. 与其他模块的关系

- **入口层** ← 状态面板嵌入
- **训练反馈层** ← 反馈驱动状态更新
- **用户画像层** ← 画像影响状态阈值
- **长期进度层** → 状态累计趋势

## 11. 暂不设计的内容

- 复杂图表（HRV、训练负荷曲线）
- 详细的可视化趋势图
