# 关键解释层设计（产品级细化版）

## 1. 文档目的

本文档定义马拉松助手关键解释层的产品级设计。关键解释层负责把训练计划中的关键训练转化为用户能理解的训练决策解释——不是"论文摘要"，而是"教练跟你说的话"。

## 2. 模块定位

关键解释层是马拉松助手区别于"训练计划生成器"和"普通 AI 聊天"的差异化模块。

它承载训练教练的"决策解释"职责：为什么安排这个训练、它对应什么能力、有什么风险、疲劳时怎么调整、有什么证据支撑。

## 3. 用户场景

### 3.1 场景 A：看到训练计划，想知道"为什么"

用户看到周二安排了"间歇跑 6×800m"，不理解为什么赛前 8 周要做这个。

用户此时的困惑：
- 这个训练主要提升什么？
- 为什么安排在周二不是周四？
- 我的水平适合做这种训练吗？

关键解释层需在此场景给出一句话的"安排原因"和一句话的"关联能力"。

### 3.2 场景 B：对某个训练有疑虑

用户膝盖有旧伤，看到"节奏跑 10km"有顾虑。

用户此时的困惑：
- 这个训练对我的旧伤有风险吗？
- 有没有替代方案？
- 如果感觉不舒服应该怎么做？

关键解释层需在此场景展示风险提示和可替代方案。

### 3.3 场景 C：想知道建议的"含金量"

用户看到训练安排，想知道这不是随便生成的。

用户此时的困惑：
- 这个安排有科学依据吗？
- 证据从哪里来？
- 证据是什么级别的（科研论文 / 训练模板 / 经验规则）？

关键解释层需在此场景连接证据可信层，展示可点击的证据编号。

### 3.4 场景 D：反馈后看到计划调整

用户前几天反馈了"本周太累"，系统调整了本周后续训练。

用户此时的困惑：
- 为什么把周四的高强度课换成了轻松跑？
- 这个调整的依据是什么？
- 调整后我还能达到本周目标吗？

关键解释层需在此场景展示"自适应解释"——解释为什么做这个调整。

## 4. 信息架构

### 4.1 逐训练解释项

每个关键训练对应一个解释项，信息层级从最重要到最次要：

```text
解释项
├── 为什么安排（why_scheduled）：一句话人话解释
├── 主要提升（primary_target）：对应什么能力
├── 风险提示（risk_alert）：需要注意什么
├── 替代方案（alternative_workout）：如果做不了可以换什么
├── 决策摘要（decision_summary）：技术性决策过程（默认折叠）
└── 证据入口（evidence_ids）：[1] [2] [3] 可点击编号
```

### 4.2 解释应该在的"位置"

解释不是独立页面，而是嵌入在训练卡的对应位置：

```text
DailyWorkoutDetailCard
├── 训练类型 + 核心指标
├── 执行步骤
├── ...
└── 操作区
    ├── [为什么这样安排？] ← 点击展开此训练的解释项
    ├── [查看证据] ← 连接证据可信层
    └── [已完成]
```

### 4.3 多周概览：本周关键课解释摘要

```text
本周关键课解释摘要
├── 周二间歇跑：提升 VO₂max，为巅峰期速度打基础 [1][3]
├── 周四节奏跑：强化乳酸阈，配速 4:50 [2]
└── 周日长距离：积累有氧耐力，关键基础课 [1][4]
```

## 5. 组件拆分

### 5.1 解释抽屉（ExplanationDrawer）

- 位置：DailyWorkoutDetailCard 操作区
- 类型：CustomElement（React 组件，轻量化 A 方案优先使用 Sheet；当前 Chainlit Markdown 阶段以折叠式抽屉等效承载）
- 职责：展示单个训练的完整解释
- 触发：用户点击"为什么这样安排？"
- 内容结构：
  - 标题：训练名称 + 日期
  - 安排原因（why_scheduled）
  - 主要提升（primary_target）
  - 风险提示（risk_alert）— 如有风险则红色醒目
  - 替代方案（alternative_workout）— 如有替代则显示
  - 决策摘要（decision_summary）— 默认折叠，可展开
  - 证据标签栏：`[1]` `[2]` `[3]`（灰色 Badge，可点击）
- 底部操作：
  - "查看证据原文" → 跳转证据抽屉
  - "我理解了" → 关闭
- 可移植性：纯数据驱动 props

### 5.2 本周解释摘要（WeekExplanationSummary）

- 位置：WeekTrainingCard 内，"本周关键课"区域
- 类型：CustomElement（React 组件）
- 职责：一行展示本周所有关键训练的解释摘要
- 每个摘要项：
  - 训练日 + 训练类型 + 安排原因（一句话）+ 证据编号
- 交互：点击 → 展开对应训练的 ExplanationDrawer

### 5.3 自适应调整解释卡（AdaptiveExplanationCard）

- 位置：反馈提交后、或入口层反馈总结区
- 类型：cl.Message + CustomElement
- 职责：解释系统为什么对训练做了调整
- 触发时机：
  - 用户提交"未完成"或"高疲劳"反馈后
  - 系统生成 adaptive_adjustment 后
- 内容：
  - 调整内容（如"周四高强度跑 → 轻松跑"）
  - 调整原因（如"检测到上周疲劳度偏高"）
  - 对本周目标的影响（如"本周总训练量不变，强度降低"）
- 交互：点击展开完整调整依据

### 5.4 训练目的标签（PurposeBadge）

- 位置：DailyWorkoutDetailCard 核心指标行旁
- 类型：Badge（shadcn/ui Badge）
- 职责：一句话概括训练目的
- 示例：
  - "提升 VO₂max"
  - "强化乳酸阈"
  - "积累有氧基础"
  - "赛前减量调整"
- 数据来源：explanation_item.primary_target 的精简版

### 5.5 风险图标（RiskIcon）

- 位置：DailyWorkoutDetailCard 和 ExplanationDrawer 中
- 类型：Icon + Tooltip
- 职责：当训练有风险时显示警示图标
- 展示逻辑：
  - 无风险：不显示
  - 低风险：灰色感叹号
  - 中风险：黄色警告
  - 高风险：红色警告
- Tooltip 内容：risk_alert 的简短版本

### 5.6 无解释空态（NoExplanationPlaceholder）

- 位置：ExplanationDrawer 内（当该训练没有解释数据时）
- 类型：占位文本
- 职责：友好说明当前训练没有详细解释
- 内容："该训练当前暂无详细解释，系统正在持续完善中。您可以在训练后反馈感受，帮助系统学习。"
- 已由 Week6 测试覆盖（test_week6_explanation_dto_contract.py）

## 6. 交互流程

### 6.1 查看训练解释

```text
[DailyWorkoutDetailCard] → [点击"为什么这样安排？"]
                         → 弹出 ExplanationDrawer
                         → 用户阅读：安排原因 → 提升目标 → 风险 → 替代
                         → 用户可选：
                             ├── 点击证据编号 → 跳转证据抽屉
                             ├── 展开决策摘要 → 查看技术依据
                             └── 点击"我理解了" → 关闭抽屉
```

### 6.2 查看本周关键课概览

```text
[WeekTrainingCard] → 本周关键课区域
                   → 展示 2-4 条解释摘要
                   → 用户点击某条 → 对应训练 ExplanationDrawer 弹出
```

### 6.3 查看自适应调整解释

```text
[提交反馈] → [系统生成 adaptive_adjustment]
            → 入口层展示 AdaptiveExplanationCard
            → 用户看到调整内容 + 原因 + 影响
            → [点击展开] → 查看完整调整依据
```

## 7. 状态设计

### 7.1 有解释态

- ExplanationDrawer 正常展示，逐项可见
- 证据编号 Badge 可点击，灰度 `[1]` `[2]` 格式（已在 output_nodes.py 实现）
- 风险提示按等级着色

### 7.2 部分解释态

- 某训练有解释但缺证据 → 展示解释但不显示证据编号
- 某训练有解释但无替代方案 → 不显示替代方案行

### 7.3 无解释态

- 该训练无解释数据：显示 NoExplanationPlaceholder
- 整个训练计划无解释面板：不渲染"查看解释"按钮

### 7.4 异常态

- explanation_panel 数据格式异常：降级为不显示解释入口，不崩溃
- evidence_ids 存在但对应 evidence_base 缺项：证据编号仍显示但不可点击
- 多周计划中某周缺解释数据：只渲染有数据的周

## 8. 与后端 / 会话数据关系（Option A 架构）

### 8.1 消费的数据结构

关键解释层从 `structured_report` 中消费：

| 数据 | 来源字段 | 用途 |
|------|------|------|
| 逐训练解释 | `training_explanation_panel[week_N][item]` | ExplanationDrawer 全部内容 |
| 安排原因 | `item.why_scheduled` | 解释展示 |
| 主要提升 | `item.primary_target` | PurposeBadge + 解释展示 |
| 风险提示 | `item.risk_alert` | RiskIcon + 解释展示 |
| 替代方案 | `item.alternative_workout` | 解释展示 |
| 决策摘要 | `item.decision_summary` | 折叠区 |
| 证据编号 | `item.evidence_ids` | 证据 Badge 渲染 |
| 证据详情 | `evidence_base` | "查看证据"跳转 |
| 自适应调整 | `adaptive_adjustment` | AdaptiveExplanationCard |
| 自适应反馈 | `adaptive_feedback` | 触发展示调整解释 |

### 8.2 FastAPI 端点（应用层，新增建议）

| 端点 | 方法 | 职责 |
|------|------|------|
| `/plan/{user_id}/week/{week_index}/explanations` | GET | 获取指定周的所有训练解释 |
| `/plan/{user_id}/day/{week_index}/{day_index}/explanation` | GET | 获取指定日训练解释 |
| `/adjustments/{user_id}` | GET | 获取当前调整记录及解释 |

### 8.3 Chainlit 层职责（展示层）

- 在 DailyWorkoutDetailCard 中嵌入"查看解释"按钮
- 点击后调用 FastAPI 获取解释数据
- 以 ExplanationDrawer（CustomElement Dialog）展示
- 证据编号点击 → 通知证据可信层弹出证据抽屉

## 10. 与其他模块的关系

关键解释层是三向桥接模块：

- **训练计划层** ← 提供需要解释的关键训练
- **用户画像层** ← 提供个性化解释背景（"因为你的目标是全马 sub330..."）
- **证据可信层** ↔ 提供可点击证据编号和原文追溯
- **训练反馈层** ↔ 反馈触发自适应解释
- **数据状态层** ← 疲劳/恢复状态影响解释内容

## 11. 暂不设计的内容

- ExplanationDrawer 的具体排版布局
- 自适应解释的具体文案模板
- 风险分级的具体阈值（低/中/高）
- 解释语言的 A/B 测试

## 12. 后续确认重点

- ExplanationDrawer 用 Dialog（居中弹窗）还是 Sheet（侧边滑出）
- 决策摘要（decision_summary）默认是展开还是折叠
- 自适应解释是否默认展示还是需要用户点击
- 本周解释摘要是否在 WeekTrainingCard 中默认显示
- 证据编号点击是直接跳转证据抽屉，还是先展开解释抽屉再提供证据入口
