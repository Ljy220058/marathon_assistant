# 马拉松助手 UI 改进路线总纲

## 1. 文档目的

本文档用于沉淀马拉松助手前端 UI 改进的总体方向、组间模块边界与后续分步确认路线。

当前阶段只定义框架，不进入具体视觉、组件、字段、配色和代码实现细节。后续每个模块将逐步确认。

## 2. 总体产品判断

马拉松助手不应简单模仿某一个跑步 App，也不应停留在普通聊天机器人形态。

建议定位为：

> 一个具备科研证据支撑的个性化马拉松训练决策助手。

核心路线：

> 以 TrainingPeaks / Garmin / Strava 的专业训练结构为骨架，  
> 以 Apple Fitness / Headspace / Duolingo / 小红书的消费级体验为表达方式，  
> 以项目已有的 RAG / GraphRAG / Decision Graph 作为可信证据链。

## 3. 核心设计理念

> 专业可信，但不压迫用户。

很多专业训练平台信息密度高，普通消费级 App 又缺少训练深度。马拉松助手应走中间路线：底层专业、表层轻量。

设计表达可以概括为：

```text
专业底层：训练周期、强度区间、恢复建议、RAG 证据、图谱决策
体验表层：卡片、进度条、低摩擦按钮、解释型文案、分层展开
```

## 4. 三条总原则

### 4.1 从“聊天输出”升级为“训练工作台”

当前界面容易形成“用户问一句，系统答一大段”的体验。未来应让用户一进入系统就知道：

- 当前处于什么训练状态；
- 本周应该做什么；
- 下一次训练是什么；
- 为什么这样安排；
- 是否存在风险；
- 完成后如何反馈。

### 4.2 从“长文本计划”升级为“结构化训练卡片”

训练计划不应主要依赖长 Markdown，而应采用：

```text
周卡片 → 日训练卡 → 关键训练解释 → 证据展开 → 反馈闭环
```

### 4.3 从“证据附属”升级为“可信度卖点”

项目的差异化不只是生成计划，而是能解释为什么这样安排，并能追溯证据来源。

证据应默认轻展示，用户需要时再展开。

## 5. 前端入口战略

后续 UI 顶级优化采用 Chainlit-first 策略：

- Chainlit：唯一主 UI 优化入口，承担训练工作台、卡片化计划、解释证据、反馈闭环等产品体验；
- FastAPI：保留为数据与服务接口层，服务外部调用、测试和后续前后端分离；
- Gradio：历史入口，标记为 deprecated，不再优化，不再作为新 UI 设计、测试覆盖和交互兼容约束。

该策略的目的不是立即删除历史代码，而是避免后续产品设计被多前端兼容牵制。新 UI 能力优先围绕 Chainlit 打透，必要的数据能力通过 FastAPI 暴露。

## 6. 总体信息架构

未来前端可抽象为八个组间模块：

```text
入口层
  ↓
用户画像层
  ↓
训练计划层
  ↓
关键解释层
  ↓
证据可信层
  ↓
训练反馈层
  ↓
数据状态层
  ↓
长期进度层
```

## 8. 组间协作关系

### 8.1 产品主链路

```text
用户画像层
  ↓
训练计划层
  ↓
关键解释层
  ↓
证据可信层
  ↓
训练反馈层
  ↓
数据状态层
  ↓
长期进度层
```

含义：画像决定计划，计划生成关键训练，关键训练需要解释，解释需要证据，执行后产生反馈，反馈改变状态，状态影响长期进度。

### 8.2 用户体验链路

```text
入口层
  ↓
今日任务 / 本周目标
  ↓
训练卡片
  ↓
为什么这样练
  ↓
查看证据
  ↓
完成反馈
  ↓
获得下一步建议
```

### 8.3 技术数据链路

```text
profile
  ↓
structured_training_plan
  ↓
training_plan_weeks
  ↓
training_explanation_panel
  ↓
evidence_base / evidence_ids
  ↓
workout_feedback
  ↓
adaptive_feedback / adaptive_adjustment
  ↓
analytics_events
```

## 9. 分阶段改进路线

### 阶段一：现有能力卡片化

目标：不改变核心生成逻辑，先让现有结果更像 App，而不是长文本回复。

覆盖模块：训练计划层、关键解释层、证据可信层、训练反馈层。

### 阶段二：建立训练工作台

目标：用户进入后看到自己的训练状态、下一步任务与反馈入口。

覆盖模块：入口层、数据状态层、长期进度层。

### 阶段三：建立长期训练陪伴感

目标：从一次性生成计划，升级为陪伴完整训练周期。

覆盖模块：长期进度层、反馈层、数据状态层、计划调整链路。

### 阶段四：建立专业可信品牌感

目标：把 RAG / GraphRAG / Decision Graph 的优势转化为用户能感知的信任体验。

覆盖模块：证据可信层、关键解释层、数据状态层。

## 10. 设计优先级

| 优先级 | 模块 | 原因 |
|---|---|---|
| P0 | 训练计划层 | 用户最核心、最常看 |
| P0 | 关键解释层 | 已有基础，最能体现智能性 |
| P0 | 证据可信层 | 项目差异化能力 |
| P1 | 训练反馈层 | 决定是否能形成闭环 |
| P1 | 入口层 | 决定产品第一印象 |
| P2 | 数据状态层 | 决定专业感和持续使用 |
| P2 | 长期进度层 | 决定 20 周计划体验 |
| P3 | 视觉品牌层 | 最后统一风格，不宜一开始重投入 |

## 11. 当前阶段不做的事情

当前阶段不做：

- 不改代码；
- 不定配色；
- 不画具体页面；
- 不讨论 CSS；
- 不引入新前端框架；
- 不删除 Gradio 历史代码；
- 不一次性设计所有细节。

当前只做：方向框架、模块边界、前端入口战略、后续确认顺序。

## 12. 后续确认顺序

建议按以下顺序逐步确认：

1. 训练计划层：多周计划、周卡片、每日训练卡；
2. 关键解释 + 证据层：为什么这样练、证据如何展开；
3. 入口工作台层：用户进入后看到的首页状态和下一步任务；
4. 训练反馈层：完成反馈、自适应调整、下一步建议；
5. 数据状态与长期进度层：周期进展、完成度、风险与复盘。

## 13. 本轮结论

未来路线建议定义为：

> 混合型马拉松训练工作台：用结构化计划承载训练任务，用关键解释承载教练思考，用证据抽屉承载可信来源，用反馈闭环承载长期个性化。

一句话总结：

> 不是把聊天界面做漂亮，而是把它升级为一个可执行、可解释、可反馈、可追踪的训练系统。
