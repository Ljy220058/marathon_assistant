# 训练反馈层设计（产品级细化版）

## 1. 文档目的

本文档定义马拉松助手训练反馈层的产品级设计。训练反馈层负责把用户真实执行情况转化为后续计划调整和状态判断的输入，是"生成计划 → 执行 → 反馈 → 自适应调整"闭环的关键环节。

## 2. 模块定位

训练反馈层是从"一次性计划生成"走向"长期自适应教练"的关键闭环。

它需要让用户低成本反馈训练完成情况，并让系统把反馈转化为可感知的下一步建议。反馈本身应该让用户感到"有用"而非"麻烦"。

## 3. 用户场景

### 3.1 场景 A：完成训练，愉快反馈

用户按计划完成了今天的轻松跑，感觉不错。

用户此时的困惑：
- 需要填什么？
- 填完系统会做什么？

反馈层需在此场景提供极简反馈入口：完成/未完成 → 完成质量 → 可选详情。

### 3.2 场景 B：没完成训练，想解释原因

用户今天本应跑间歇跑，但实在太累了没去。

用户此时的困惑：
- 没完成会影响整个计划吗？
- 明天训练会调整吗？

反馈层需在此场景支持"未完成 + 原因"，并触发自适应调整。

### 3.3 场景 C：训练中有不适

用户完成了训练，但膝盖有点疼。

用户此时的困惑：
- 要不要告诉系统？
- 告诉系统后会不会整个计划被大改？

反馈层需在此场景收集不适信息，触发风险提示和可能的调整建议。

### 3.4 场景 D：训练后看到反馈结果

用户提交了反馈，想知道系统怎么看。

用户此时的困惑：
- 反馈被收到了吗？
- 下次训练有变化吗？
- 我现在的状态是什么？

反馈层需在此场景展示反馈总结卡和适应性调整建议。

## 4. 信息架构

### 4.1 反馈输入

```text
训练反馈输入（按信息深度分级）
├── 一级：完成状态（必填）
│   └── ✅ 完成 / ❌ 未完成
├── 二级：完成质量（完成时）
│   └── 轻松完成 / 正常完成 / 勉强完成
├── 三级：身体感知（可选）
│   ├── 主观疲劳：低 / 中 / 高
│   ├── 身体不适：无 / 膝盖 / 脚踝 / 髋 / 腰背 / 其他
│   └── 睡眠恢复：良好 / 一般 / 差
└── 四级：备注（可选）
    └── 自由文本
```

### 4.2 反馈结果

```text
训练反馈卡
├── 反馈确认（"已记录你今天完成了轻松跑 8km"）
├── 状态摘要
│   ├── 本周完成度：3/4
│   ├── 当前疲劳水平：正常
│   └── 恢复状态：良好
├── 下一步建议（如有调整）
│   └── "明天计划不变，继续轻松跑 6km"
└── 操作：[查看完整计划] [查看解释]
```

## 5. 组件拆分

### 5.1 反馈快速入口（FeedbackQuickEntry）

- 位置：入口层 TodayWorkoutCard 下方、DailyWorkoutDetailCard 操作区
- 类型：cl.Action 按钮组
- 职责：最低摩擦的反馈提交
- 步骤：
  1. 点击"✅ 已完成"或"❌ 未完成"
  2. 如果已完成 → 选择完成质量
  3. 可选展开 → 疲劳/不适/睡眠/备注
  4. 提交

### 5.2 反馈详细表单（FeedbackDetailForm）

- 位置：反馈快速入口展开后
- 类型：CustomElement（React 组件，内嵌表单）
- 职责：收集完整反馈信息
- 字段：
  - 完成质量（Select / RadioGroup）
  - 主观疲劳（Slider / Select）
  - 身体不适（MultiSelect + 自定义输入）
  - 睡眠质量（Select）
  - 备注（Textarea）
- 可移植性：纯数据驱动 props

### 5.3 训练反馈卡（TrainingFeedbackCard）

- 位置：反馈提交后展示
- 类型：cl.Message + CustomElement
- 职责：展示反馈结果和状态更新
- 内容：
  - 反馈确认文本
  - 状态摘要（本周完成度 / 疲劳 / 恢复）
  - 自适应调整摘要（如有）
  - 下一步建议
- 已有基础实现：`plan_ui.build_training_feedback_card`

### 5.4 自适应调整提示（AdaptiveAdjustmentNotice）

- 位置：TrainingFeedbackCard 内或独立展示
- 类型：CustomElement（Card + Badge）
- 职责：提示用户训练计划发生了调整
- 展示：
  - 调整类型 Badge（强度下调 / 增加恢复 / 无调整）
  - 调整内容（如"明天间歇跑改为轻松跑"）
  - 调整原因（一行）
  - 展开链接 → AdaptiveExplanationCard

## 6. 交互流程

### 6.1 完成训练反馈

```text
[TodayWorkoutCard] → [点击"✅ 已完成"]
                    → 反馈快速入口展开：完成质量选择
                    → [选择"正常完成"] → 可选：展开详情
                    → [提交] → TrainingFeedbackCard 展示反馈结果
                             → 如有调整 → AdaptiveAdjustmentNotice
```

### 6.2 未完成训练反馈

```text
[TodayWorkoutCard] → [点击"❌ 未完成"]
                    → 反馈详细表单展开
                    → 选择原因 / 疲劳 / 不适
                    → [提交] → TrainingFeedbackCard + AdaptiveAdjustmentNotice
```

## 7. 状态设计

### 7.1 待反馈态

- 当天有训练，未提交反馈
- FeedbackQuickEntry 展示在主操作区

### 7.2 已反馈态

- TrainingFeedbackCard 展示
- 当天入口层更新为反馈结果

### 7.3 无可反馈态

- 当天无训练，不展示反馈入口
- 过去训练未反馈：可选展示提醒

### 7.4 异常态

- 反馈解析失败：展示原始输入 + 重试
- 自适应调整生成失败：仍展示反馈确认，但提示"系统暂未生成调整建议"

## 8. 与后端 / 会话数据关系（Option A 架构）

### 8.1 FastAPI 端点

| 端点 | 方法 | 职责 |
|------|------|------|
| `/feedback/{user_id}` | POST | 提交训练反馈 |
| `/feedback/{user_id}/latest` | GET | 获取最近反馈和调整结果 |

### 8.2 消费/生产的数据

| 数据 | 方向 | 用途 |
|------|:---:|------|
| workout_feedback | 写入 | 反馈数据持久化 |
| adaptive_feedback | 读取 | 反馈总结展示 |
| adaptive_adjustment | 读取 | 调整提示展示 |

## 9. Chainlit 落地方式

- **Actions**：已完成/未完成按钮（已实现）
- **CustomElement**：FeedbackDetailForm（新增）
- **现有实现保留**：`plan_ui` 反馈卡片逻辑、`logic.py` 解析与写回

## 10. 与其他模块的关系

- **入口层** ← 反馈入口展示
- **训练计划层** ← 反馈目标训练
- **用户画像层** → 反馈可修正画像
- **数据状态层** → 反馈进入状态计算
- **关键解释层** → 触发自适应解释
- **长期进度层** → 反馈累计为阶段复盘
