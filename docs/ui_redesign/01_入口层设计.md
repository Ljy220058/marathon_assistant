# 入口层设计（产品级细化版）

## 1. 文档目的

本文档定义马拉松助手前端入口层的产品级设计。入口层负责让用户一进入系统就知道可以做什么、当前处于什么状态、下一步应该做什么。

## 2. 模块定位

入口层是用户进入训练系统后的第一接触面，应从"聊天输入框"升级为"训练工作台入口"。

目标是降低首次使用的不确定感，让用户快速理解系统能力与当前任务。

## 3. 用户场景

### 3.1 场景 A：首次进入

用户第一次打开马拉松助手。系统尚未生成训练计划，画像可能未完整填写。

用户此时的困惑：
- 这个系统能做什么？
- 我需要先填什么？
- 从哪里开始？

入口层需在此场景下引导用户完成画像填写，再进入计划生成。

### 3.2 场景 B：训练周期中进入

用户已完成画像和计划生成，当前处于训练周期的某一天。

用户此时的困惑：
- 今天有训练吗？
- 本周进度如何？
- 上次训练后有没有调整建议？

入口层需在此场景展示今日任务、本周摘要和关键状态。

### 3.3 场景 C：训练完成后进入

用户刚提交完一次训练反馈。

用户此时的困惑：
- 反馈结果是什么？
- 下次训练有变化吗？
- 我的恢复状态怎么样？

入口层需在此场景优先展示反馈结果和适应性调整。

### 3.4 场景 D：闲时自由探索

用户没有明确训练任务，只是想了解训练知识或回顾计划。

用户此时的困惑：
- 我能问什么问题？
- 之前生成的计划在哪里看？

入口层需在此场景保留自由问答入口和计划回顾入口。

## 4. 信息架构

入口层按会话状态分为三级信息层级：

### 4.1 第一层：状态摘要（始终可见）

```text
状态摘要
├── 训练周期阶段标识（如 "第 3 周 / 12 周 · 基础期"）
├── 今日训练是否存在
│   ├── 有训练：简短任务摘要（如 "今日：轻松跑 8km · Z2"）
│   └── 无训练：休息日提示或交叉训练建议
└── 本周完成度简标（如 "本周已完成 2/4"）
```

### 4.2 第二层：主操作区（按场景变化）

```text
主操作区
├── 无计划时：计划生成入口（主 CTA）
├── 有计划未反馈时：今日训练卡 + 反馈入口
├── 刚反馈后：反馈总结卡 + 调整建议
└── 完全空闲时：推荐问题或探索入口
```

### 4.3 第三层：辅助入口（始终可访问）

```text
辅助入口
├── 查看完整计划
├── 查看长期进度
├── 自由问答
└── 查看/编辑画像
```

## 5. 组件拆分

### 5.1 状态条（StatusBar）

- 位置：采用轻量化 A 方案，作为入口层顶部状态摘要展示；在 Astro 页面中优先以顶栏状态区模拟 sticky 体验
- 职责：展示训练周期阶段、本周摘要
- 信息约束：只显示周次 / 阶段、今日训练摘要、本周完成度三类信息
- 更新时机：进入会话时加载、计划变更时刷新
- 交互：只读展示，不承载复杂操作

### 5.2 今日训练卡（TodayWorkoutCard）

- 位置：状态条下方
- 职责：展示今日训练摘要
- 字段：
  - 训练类型标签（轻松跑/间歇跑/长距离/休息/力量）
  - 核心指标（距离、配速、心率区间）
  - 关键标记（是否为本周关键训练）
- 交互：
  - 点击可展开完整训练详情
  - 完成后可触发反馈入口

### 5.3 反馈入口（FeedbackEntry）

- 位置：今日训练卡下方或替代今日训练卡
- 职责：引导用户提交训练反馈
- 展示模式：
  - 当天有训练：展示"完成训练？"引导按钮
  - 当天无训练：不展示
  - 已提交反馈：展示反馈摘要

### 5.4 计划生成引导（PlanGenerationGuide）

- 位置：无计划时的主操作区
- 职责：引导用户生成第一份训练计划
- 展示：简短说明 + 生成计划按钮
- 前置条件：画像已完整

### 5.5 画像完成引导（ProfileCompletionGuide）

- 位置：画像不完整时的主操作区
- 职责：引导用户完成必要画像字段
- 展示：缺失字段提示 + 填写入口

### 5.6 操作菜单（ActionMenu）

- 位置：入口欢迎区的左侧卡片栏，由 `LeftActionRail` 承载，不再使用消息下方横排 actions 作为主入口。
- 职责：提供常驻导航，并把高频入口按业务职责分组。
- 展示方式：左侧竖直分组卡片，右侧保留当前状态与下一步提示。
- 分组：
  - 训练计划：极速画像、完整画像、自适应调整
  - 知识库：搜索知识图谱、交叉研究实体、管理知识库
  - 界面：刷新画像、隐藏/打开侧边栏
- 组间实现方法说明：`setup.py` 负责构造 `LeftActionRail` props；`public/elements/LeftActionRail.jsx` 负责卡片化展示并通过 `callAction()` 触发既有前端动作；`actions.py` 继续承担原有业务动作，避免重写画像、知识库或侧边栏逻辑。

### 5.7 欢迎区（WelcomeArea）

- 位置：首次进入时替代状态条
- 职责：介绍系统能力
- 内容：
  - 一句话定位（如"你的 AI 马拉松教练"）
  - 核心能力说明（计划生成 / 训练解释 / 证据可信）
  - 开始按钮

## 6. 交互流程

### 6.1 首次用户进入

```text
[进入] → 欢迎区 → [点击开始] → 检查画像完整性
                                      ├── 画像完整 → 计划生成引导
                                      └── 画像不完整 → 画像完成引导
```

### 6.2 老用户进入（有计划、有今日训练）

```text
[进入] → 加载会话状态 → 展示状态条
                      → 展示今日训练卡
                      → 展示辅助入口菜单
                      → [用户完成训练] → 反馈入口展开
                                       → [提交反馈] → 展示反馈总结卡 + 调整建议
```

### 6.3 老用户进入（有计划、今日无训练）

```text
[进入] → 加载会话状态 → 展示状态条（休息日提示）
                      → 展示辅助入口菜单
                      → 可选展示：本周回顾摘要
```

### 6.4 自由问答

```text
[任意时刻] → 用户在聊天框输入问题 → 系统以 QA 模式响应
                                   → 响应中嵌入证据引用和解释入口
```

## 7. 状态设计

### 7.1 加载态

- 状态条区域展示骨架屏或加载指示
- 辅助入口菜单不可用或灰显

### 7.2 空态

- 首次进入：展示欢迎区
- 画像不完整：展示画像完成引导
- 无计划：展示计划生成引导
- 计划中但今日无训练：展示休息日提示

### 7.3 完成态

- 今日训练已反馈：展示反馈摘要 + 调整建议
- 本周全部完成：展示本周总结

### 7.4 异常态

- 会话状态加载失败：展示重试入口 + 降级到基础聊天模式
- 计划数据缺失但之前生成过：展示重新加载或重新生成入口

## 8. 与后端 / 会话数据关系

入口层消费以下数据结构：

| 数据 | 来源 | 用途 |
|------|------|------|
| 用户画像完整性 | `state.user_profile` | 决定展示画像引导还是计划引导 |
| 训练计划 | `state.structured_training_plan` | 提取周编号、今日训练 |
| 本周完成度 | `state.training_feedback` 累计 | 状态条展示 |
| 最近反馈 | `state.adaptive_feedback` / `adaptive_adjustment` | 反馈总结卡 |
| 会话状态 | 前端会话状态 | 判断首次进入 / 老用户 |

## 9. Astro 落地方式

### 9.1 利用 Astro 现有能力

- **页面组件**：适用于欢迎区和状态条
- **按钮组**：适用于辅助入口菜单
- **卡片组件**：适用于状态条和今日训练卡
- **输入框**：保留为自由问答入口

### 9.2 落地步骤建议

1. 将当前页面加载逻辑改造为按会话状态分支：
   - 无画像 → 展示欢迎区 + 画像填写入口
   - 有画像无计划 → 展示计划生成引导
   - 有画像有计划 → 展示状态条 + 今日训练卡 + 操作菜单

2. 新增 `render_entry_status_bar()` 渲染状态条

3. 新增 `render_today_workout_card()` 渲染今日训练卡

4. 将辅助入口封装为按钮组

### 9.3 不涉及的部分

- 不修改旧前端运行线代码
- 不新增额外独立页面

## 10. 与其他模块的关系

入口层与以下模块协作：

- **画像层**：决定用户当前训练身份与默认入口内容
- **计划层**：提供本周计划与今日任务入口
- **反馈层**：提供训练完成后的反馈入口
- **数据状态层**：展示当前状态与风险摘要
- **长期进度层**：展示周期进展入口

## 11. 暂不设计的内容

- 具体的颜色、字号、间距
- 欢迎区的完整文案
- 操作菜单的图标方案
- 骨架屏的具体样式
- 移动端适配策略

## 12. 后续确认重点

- 状态条是否始终置顶（sticky），还是作为对话流中的一条消息
- 今日训练卡是自动展示还是需要用户点击触发
- 辅助入口用按钮（Actions）还是用对话中的快速回复（Quick Replies）
- 入口层中自由问答的地位——是作为主交互方式之一，还是退到辅助角色
