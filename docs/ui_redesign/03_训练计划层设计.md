# 训练计划层设计（产品级细化版）

## 1. 文档目的

本文档定义马拉松助手训练计划层的产品级设计。训练计划层是前端 UI 改进的核心模块，负责展示多周训练计划、周级目标、每日训练任务、关键训练标记，并为解释、证据、反馈提供入口。

## 2. 模块定位

训练计划层应从"长 Markdown 周计划"升级为"多周训练卡片系统"。

它是用户最常查看、最直接执行的模块，也是整个产品从"AI 生成一份训练计划"升级为"长期训练陪伴系统"的核心载体。

## 3. 用户场景

### 3.1 场景 A：首次拿到计划，浏览全貌

用户刚生成了一份 12 周训练计划，想快速了解整体安排。

用户此时的困惑：
- 总共几周？分几个阶段？
- 第一周要做什么？
- 每周训练几天？

训练计划层需在此场景提供阶段总览 + 首周展开 + 其余周收缩的渐进式信息架构。

### 3.2 场景 B：今天要训练，查看今日任务

用户打开系统，想知道今天练什么。

用户此时的困惑：
- 今天是什么训练？
- 具体怎么练？（热身、主课、放松）
- 心率控制在什么区间？

训练计划层需在此场景优先展示今日训练卡，且信息密度从高到低：训练类型 → 核心指标 → 具体步骤。

### 3.3 场景 C：查看某一周安排

用户想回顾第 8 周（巅峰期）的训练安排。

用户此时的困惑：
- 那一周有几个质量课？
- 长距离跑多远？
- 关键训练是哪几个？

训练计划层需提供周级导航，让用户快速跳转到任意一周。

### 3.4 场景 D：长周期计划中，不想看到重复

用户拿了 20 周计划，担心每周看起来都差不多。

用户此时的困惑：
- 每周有什么不同？
- 负荷是在增加还是减少？
- 阶段之间有明显的过渡吗？

训练计划层需通过阶段标记、负荷递进说明、防重复签名来体现周间差异。

### 3.5 场景 E：首周执行

用户看完计划，想开始第一周的训练。

用户此时的困惑：
- 从哪一天开始？
- 第一步做什么？
- 训练过程中能查看解释吗？

训练计划层需提供首周执行入口，连接训练执行和反馈。

## 4. 信息架构

训练计划层采用 **三级渐进式信息架构**：

### 4.1 第一级：阶段总览（计划级的"目录"）

```text
阶段总览
├── 计划元信息（目标 / 周数 / 起始日期）
├── 阶段拆分条
│   ├── [基础期] W1-W4  ·  建立有氧基础
│   ├── [建设期] W5-W10 ·  提升专项能力
│   ├── [巅峰期] W11-W14 · 赛前冲刺
│   └── [减量期] W15-W16 · 比赛调整
└── 首周行动建议（前 3 条可见，其余可展开）
```

### 4.2 第二级：周级视图（每周一张卡）

```text
周级卡片
├── 周标识（第 N 周 · 阶段名称 · 负荷标签）
├── 本周目标（一句话）
├── 负荷递进说明（与上周的对比）
├── 每日训练缩略行（7 天横向或紧凑纵向）
│   ├── 周一：轻松跑 8km · Z2
│   ├── 周二：间歇跑 6×800m · Z7-Z8
│   ├── ...
│   └── 周日：长距离 20km · Z3
├── 关键训练标记（周二/周四/周日 高亮）
├── 本周摘要（训练 X 天 | 质量课 N 节 | 长距离 Y km | 周跑量 Z km）
└── 展开按钮 → 进入每日详情
```

### 4.3 第三级：每日训练卡（单日详情）

```text
每日训练卡
├── 训练类型标签（Badge：轻松跑 / 间歇跑 / 节奏跑 / 长距离 / 休息 / 力量）
├── 核心指标行
│   ├── 距离：8km
│   ├── 配速：5:45-6:15 /km
│   └── 心率区间：Z2 (108-126 bpm)
├── 执行步骤
│   ├── 🏃 热身：慢跑 2km + 动态拉伸 (2km)
│   ├── 🎯 主课：轻松跑 5km，保持 Z2 (5km)
│   └── 🧘 放松：慢跑 1km + 静态拉伸 (1km)
├── 场地建议：公园 / 田径场 / 跑步机
├── 备注
├── 关键训练标记（如适用）
└── 操作：查看解释 | 开始训练 | 标记完成
```

## 5. 组件拆分

### 5.1 阶段总览条（PhaseOverviewBar）

- 位置：训练计划顶部
- 类型：CustomElement（React 组件）
- 职责：展示计划元信息 + 阶段拆分
- 字段：
  - 目标赛事 / 目标描述
  - 总周数
  - 阶段列表（名称、起止周、目标）
  - 当前所在阶段高亮
- 交互：点击某阶段 → 跳转到该阶段第一周
- 可移植性：纯数据驱动 props

### 5.2 周级导航（WeekNavigator）

- 位置：阶段总览条下方或侧边
- 类型：CustomElement（React 组件）
- 职责：提供所有周的快速跳转
- 展示模式：
  - 长计划（>= 8 周）：按阶段分组，默认只展示当前阶段
  - 短计划（< 8 周）：平铺所有周
- 交互：点击某周 → 展开该周详情
- 可移植性：纯数据驱动 props

### 5.3 周级训练卡（WeekTrainingCard）

- 位置：主内容区
- 类型：CustomElement（React 组件，Card + Table/Grid）
- 职责：展示单周完整训练安排
- 默认态（轻量化 A 方案）：当前周摘要可见，7 天只显示缩略行
- 展开态：用户点击某一天后再显示该日详细 DailyWorkoutDetailCard，不默认展开全部日详情
- 字段（来自 WeekPlan）：
  - week_index, phase, week_goal
  - load_level + load_progression_note
  - days[7]（DayPlan 列表）
  - key_workouts, action_suggestions
  - execution_reminder
- 特殊标记：
  - 当前周：视觉突出（边框高亮或背景区分）
  - 已完成周：灰显 + 完成标记
  - 未来周：正常展示
- 可移植性：纯数据驱动 props

### 5.4 每日训练详情卡（DailyWorkoutDetailCard）

- 位置：周级卡片内展开或独立展示
- 类型：CustomElement（React 组件）
- 职责：展示单日训练的完整信息
- 字段（来自 DayPlan）：
  - day（周一~周日）
  - training_type + 对应 Badge 颜色
  - warmup + warmup_km
  - main_set + main_km
  - cooldown + cooldown_km
  - venue
  - notes
- 心率/配速区间展示：
  - 从用户画像衍生（LTHR 九区）
  - 在训练卡中标注目标区间
- 操作按钮：
  - "为什么这样安排？" → 跳转关键解释层
  - "查看证据" → 打开证据抽屉
  - "已完成" → 触发反馈入口
- 可移植性：纯数据驱动 props

### 5.5 关键训练标记（KeyWorkoutBadge）

- 位置：在周级卡片和每日详情卡中
- 类型：Badge 组件（shadcn/ui Badge）
- 职责：标记本周关键训练
- 视觉：不同于普通训练类型 Badge（如用实心/边框/颜色区分）
- 数据来源：WeekPlan.key_workouts

### 5.6 首周执行入口（FirstWeekExecutionEntry）

- 位置：训练计划末尾或独立卡片
- 类型：cl.Message + cl.Action
- 职责：引导用户开始第一周训练
- 展示：
  - 首周行动建议列表
  - "开始第一周训练" 主 CTA
- 交互：点击 → 进入首周日级详情 + 训练执行流程

### 5.7 负荷指示器（LoadIndicator）

- 位置：周级卡片内
- 类型：CustomElement（Progress + Badge）
- 职责：可视化周负荷水平
- 数据来源：WeekPlan.load_level（Enum）
- 展示：
  - low → 绿色 + 低
  - medium → 黄色 + 中
  - high → 橙色 + 高
  - recovery → 蓝色 + 恢复
  - taper → 灰色 + 减量
  - race → 红色 + 比赛

### 5.8 月历课表组件（MonthlyTrainingCalendar）

- 位置：周级训练卡之后，作为“一个月可点击日历课表”主视图。
- 类型：CustomElement（React 组件，Calendar Grid + Sheet）。
- 职责：将结构化多周计划转换为按日期排列的月历，用户点击任意日期后在右侧抽屉查看当日课表详情。
- 字段（来自 `structured_report.monthly_training_calendar.days[]`）：
  - date, day_label, week_index, day_index
  - training_type, training_type_label, workout_type
  - zone_range, zone_label, intensity_target
  - warmup, main_set, cooldown, alternative, training_objective
  - evidence_tier, evidence_tier_label, source, evidence_ids
- 强度展示：统一使用 Z1-Z9 中文术语，配速仅作为参考，不作为固定执行目标。
- 证据分层：
  - `action_library`：动作库课表
  - `kb_fallback`：动作库无直接证据时，基于其他知识库内容生成参考课表
  - `plan_only`：仅保留基础计划骨架
- 空态处理：Markdown 兜底渲染不再逐日输出“课表证据不足”空卡；若所有每日课表均缺证据，仅展示一条汇总提示。
- 可移植性：组件仅消费 props，不绑定 Chainlit 会话状态，后续可迁移到 React Native 的月历/日详情模型。

## 6. 交互流程

### 6.1 查看完整计划

```text
[计划生成完毕] → 渲染 PhaseOverviewBar（自动展开）
               → 渲染 WeekNavigator（默认选中第 1 周）
               → 渲染 WeekTrainingCard（第 1 周，展开态以示欢迎）
               → 用户浏览：
                   ├── 点击其他周 → 切换展示对应 WeekTrainingCard
                   ├── 点击某天 → 展开 DailyWorkoutDetailCard
                   ├── 点击"为什么这样安排" → 跳转关键解释层
                   └── 滚动到末尾 → 看到 FirstWeekExecutionEntry
```

### 6.2 查看今日训练（从入口层进入）

```text
[入口层 TodayWorkoutCard] → [点击查看详情]
                           → 展示本周 WeekTrainingCard（当前周高亮 + 今日训练日高亮）
                           → 用户可：
                               ├── 查看今日详细步骤
                               ├── 浏览本周其他日
                               └── 标记完成 → 触发反馈入口
```

### 6.3 长计划导航（>= 8 周）

```text
[WeekNavigator] → 默认展示当前阶段（如基础期 W1-W4）
                → 用户点击另一阶段 → 展开该阶段的周列表
                → 用户点击某周 → 主区域切换到对应 WeekTrainingCard
```

### 6.4 首周执行

```text
[FirstWeekExecutionEntry] → [点击"开始第一周训练"]
                          → 主区域切换展示第 1 周 WeekTrainingCard
                          → 每日训练卡附带"开始训练"/"已完成"操作
                          → 用户标记完成后 → 触发反馈层
```

## 7. 状态设计

### 7.1 加载态

- 计划生成中：PhaseOverviewBar 区域展示骨架屏
- 周级卡片：skeleton 占位

### 7.2 空态

- 尚未生成计划：展示"生成你的第一份训练计划"引导（连接入口层）
- 计划生成失败：展示重试入口 + 错误提示（已有 `render_plan_retry_md`）

### 7.3 正常态

- 周卡片默认收缩，首周或当前周展开
- 已完成周灰显（需要反馈数据支撑周完成状态）

### 7.4 完成态

- 某天训练已反馈：对应 DailyWorkoutDetailCard 显示完成标记
- 整周全部完成：周级卡片显示"本周已完成"标记

### 7.5 异常态

- 周计划数据缺失某天：不渲染该天或显示"待生成"
- 训练类型无法映射到 Badge：显示原始文本
- DayPlan 字段为空：显示占位符而非崩溃

## 8. 与后端 / 会话数据关系（Option A 架构）

### 8.1 消费的数据结构

训练计划层消费 `structured_report` 中以下字段：

| 数据 | 来源字段 | 用途 |
|------|------|------|
| 计划概览 | `training_plan_overview` | PhaseOverviewBar |
| 阶段划分 | `phase_summary` | PhaseOverviewBar 阶段条 |
| 全部周数据 | `training_plan_weeks` | WeekNavigator + WeekTrainingCard |
| 每日训练 | `training_plan_weeks[].days[]` | DailyWorkoutDetailCard |
| 月历课表 | `monthly_training_calendar` | MonthlyTrainingCalendar |
| 结构化每日课表 | `daily_schedule_cards` | 日期详情抽屉 / App 日详情 |
| 证据分层 | `evidence_tier_map` | 课表可信状态 Badge |
| 训练解释 | `training_explanation_panel` | "为什么这样安排"连接 |
| 自适应调整 | `adaptive_adjustment` | 计划变动时更新展示 |
| 证据链 | `evidence_base` | "查看证据"连接 |

### 8.2 FastAPI 端点（应用层，新增建议）

| 端点 | 方法 | 职责 |
|------|------|------|
| `/plan/{user_id}` | GET | 获取当前训练计划摘要（周列表 + 当前周） |
| `/plan/{user_id}/week/{week_index}` | GET | 获取指定周完整数据 |
| `/plan/{user_id}/day/{week_index}/{day_index}` | GET | 获取指定日训练详情 |
| `/plan/{user_id}` | POST | 生成/重新生成训练计划 |
| `/training-calendar` | POST | 基于当前查询与画像生成月历课表数据 |
| `/training-calendar/day-detail/{day_index}` | GET | 返回指定日详情接口占位契约，客户端可按完整日历数据侧查 |
| `/zone-reference` | GET | 返回 Z1-Z9 中文强度术语与 LTHR 百分比说明 |
| `/evidence-tier-reference` | GET | 返回动作库、知识库回退、基础计划三类证据状态说明 |

### 8.3 Chainlit 层职责（展示层）

- 调用 FastAPI 获取计划数据
- 用 CustomElement 渲染训练卡片
- 接收用户交互（展开/折叠/跳转/标记完成）
- 不直接解析 `structured_report`（改为调用 API）

### 8.4 当前代码与目标架构的差距

| 当前实现 | 目标架构 | 差距 |
|------|------|------|
| `legacy_ui._render_structured_training_plan_md` 输出全量 Markdown | 分步卡片化渲染 | 用 CustomElement 替代 Markdown |
| Week Navigator 仅在 `>= 8` 周时显示 | 所有计划均显示 | 去掉周数下限 |
| Daily 使用 `<details>` 折叠 | CustomElement Card 组件 | 组件化 |
| plan_ui 仅做首周执行、反馈、解释卡片 | plan_ui 成为计划层主渲染器 | 大幅扩展 |

## 9. Chainlit 落地方式

### 9.1 利用 Chainlit 原生能力

- **CustomElement**：PhaseOverviewBar、WeekNavigator、WeekTrainingCard、DailyWorkoutDetailCard
  - 底层 React + shadcn/ui：Card、Badge、Progress、Accordion、Tabs、ScrollArea
- **Actions**：首周执行入口、查看解释、标记完成
- **Messages**：阶段说明文案、告警提示

### 9.2 CustomElement 文件规划

| 文件 | 组件 | 接收 props |
|------|------|------|
| `public/elements/PhaseOverviewBar.jsx` | PhaseOverviewBar | `plan_meta`, `phase_summary`, `current_week` |
| `public/elements/WeekNavigator.jsx` | WeekNavigator | `weeks[]`, `current_week`, `completed_weeks[]` |
| `public/elements/WeekTrainingCard.jsx` | WeekTrainingCard | `week_index`, `phase`, `week_goal`, `load_level`, `days[7]`, `key_workouts`, `action_suggestions`, `execution_reminder`, `is_current_week`, `is_completed` |
| `public/elements/DailyWorkoutDetailCard.jsx` | DailyWorkoutDetailCard | `day`, `training_type`, `warmup`, `main_set`, `cooldown`, `venue`, `notes`, `km`, `hr_zone`, `is_key_workout`, `is_completed` |
| `public/elements/MonthlyTrainingCalendar.jsx` | MonthlyTrainingCalendar | `year`, `month`, `days[]`, `phases[]`, `evidence_summary`, `evidence_tier_map` |

### 9.3 落地步骤建议

1. **Phase 1**：新建 FastAPI 计划端点
   - `/plan/{user_id}` GET / POST
   - `/plan/{user_id}/week/{week_index}` GET
   - `/plan/{user_id}/day/{week_index}/{day_index}` GET

2. **Phase 2**：新建 PhaseOverviewBar CustomElement
   - 替代当前 `legacy_ui` 中阶段拆分的 Markdown 表格
   - 用一个 React Card + 横向阶段条（类似 Tabs 视觉）

3. **Phase 3**：新建 WeekTrainingCard CustomElement
   - 替代当前 `<details>` 折叠的 Markdown
   - 默认收缩态 = 本周目标 + 7 天缩略行
   - 展开态 = 7 天详细 DailyWorkoutDetailCard

4. **Phase 4**：新建 DailyWorkoutDetailCard CustomElement
   - 替代 `<details>` 内纯文本
   - 结构化展示：Badge（训练类型） + 步骤 + 指标 + 操作

5. **Phase 5**：新建 WeekNavigator CustomElement
   - 增强当前的周卡片导航表
   - 支持阶段分组、当前周高亮、已完成周标记

### 9.4 现有良好体验保留

- 相邻周去重检测（RepeatGuardSignature）→ **保留**
- 周负荷标签（low/medium/high/recovery/taper/race）→ **保留**，升级为彩色 Badge
- 关键训练标记 → **保留**，升级为独立 Badge 组件
- 首周执行入口 → **保留**，连接反馈层
- 训练解释面板连接 → **保留**

## 10. 训练卡与顶级 App 对标（设计参考）

### 10.1 TrainingPeaks 借鉴

- **每日训练卡的时间/距离/心率一目了然**：我们的 DailyWorkoutDetailCard 对标此模式
- **负荷图表 + 阶段递进可视化**：LoadIndicator + PhaseOverviewBar 对标

### 10.2 Nike Run Club 借鉴

- **训练卡配大图标，视觉友好**：我们的训练类型 Badge 应对标此方向
- **"开始训练"是页面最强 CTA**：入口层的 TodayWorkoutCard 对标

### 10.3 Strava 借鉴

- **已完成训练有清晰标记**：WeekTrainingCard 的"已完成周"灰显对标
- **关键指标一眼可见**：DailyWorkoutDetailCard 核心指标行对标

## 11. 与其他模块的关系

训练计划层是中枢模块，与所有其他模块协作：

- **入口层** ← 提供今日训练摘要和计划查看入口
- **用户画像层** ← 决定训练计划的内容（周期、强度、结构）
- **关键解释层** → 为每个关键训练提供"为什么这样安排"
- **证据可信层** → 为训练安排提供来源追溯
- **训练反馈层** → 接收执行后的反馈，影响下一轮计划
- **数据状态层** → 展示本周完成度、恢复状态
- **长期进度层** → 展示整个周期的进度
