# Pilot Benchmark 设计

## 0. 目标

构建一个面向耐力训练 RAG 问答的 30-50 题 pilot benchmark，用于验证证据约束 RAG 在以下方面是否优于无检索 LLM 和普通 RAG：

- 检索命中能力。
- 回答事实一致性。
- 证据可追溯性。
- 高风险问题下的安全处理能力。

该 benchmark 第一版先内部使用，不承诺公开。投稿前再根据版权、隐私和材料来源决定开放范围。

## 1. 评测对象

第一版只评测 RAG 问答入口。

暂不纳入：

- 多周训练计划完整生成。
- 长期用户训练效果。
- 真实医疗或康复诊断。
- 无明确证据的个体化处方效果。

## 2. 系统设置

实验至少包含三类系统：

| 系统 | 描述 | 目的 |
|---|---|---|
| S1 无检索 LLM | 直接让模型回答问题 | 判断模型常识与幻觉风险 |
| S2 普通 RAG | 检索上下文后直接生成回答 | 判断检索增强的基础价值 |
| S3 证据约束 RAG | 要求结论绑定证据，缺证时拒答或降级 | 验证本文方法贡献 |

模型环境：

- 本地 Ollama 模型：待确认具体模型名和版本。
- 主流 API 模型：待确认供应商、模型名、版本和调用日期。

## 3. 题型结构

第一版建议 36 题，便于三类题型均衡分布，也方便后续扩展到 45 或 48 题。

| 题型 | 数量建议 | 核心能力 | 示例方向 |
|---|---:|---|---|
| 事实抽取 | 12 | 从证据中准确抽取定义、数值、原则或建议 | 周期化定义、日志记录原因、营养原则 |
| 应用推理 | 12 | 基于证据进行有限场景化建议 | 不同水平跑者如何调整训练重点 |
| 风险安全 | 12 | 识别风险、缺证拒答、建议降级或专业求助 | 伤痛、过度训练、高温、心率异常 |

扩展到 50 题时，可优先增加风险安全题和跨证据应用推理题。

## 4. 样本字段

每个样本建议采用结构化 JSON 或表格维护，字段如下：

| 字段 | 说明 | 是否必填 |
|---|---|---|
| `qid` | 样本编号 | 是 |
| `category` | 事实抽取 / 应用推理 / 风险安全 | 是 |
| `question` | 用户问题 | 是 |
| `expected_answer` | 标准答案或要点评分规则 | 是 |
| `evidence_ids` | 证据材料 ID | 是 |
| `evidence_locations` | 页码、chunk_id、段落或文件定位 | 是 |
| `answerable` | 知识库是否足以回答 | 是 |
| `safety_required` | 是否需要安全提示、拒答或降级 | 是 |
| `rubric` | 人工评分标准 | 是 |
| `notes` | 标注备注 | 否 |

## 5. 指标设计

主表保留 5-8 个核心指标，详细指标放附录或补充材料。

建议主指标：

| 维度 | 指标 | 说明 |
|---|---|---|
| 检索 | Recall@5 | 是否检索到标准证据块或同文档证据 |
| 检索 | MRR@5 | 标准证据出现位置 |
| 生成 | Faithfulness | 回答是否受上下文支持 |
| 生成 | Answer Relevancy | 回答是否切题 |
| 证据追踪 | Claim Evidence Coverage | 关键结论中有证据支撑的比例 |
| 安全 | Safety Compliance Rate | 风险题中正确拒答、降级或提示专业帮助的比例 |
| 幻觉 | Unsupported Claim Rate | 无证据或错证据支撑的关键结论比例 |

指标口径必须固定，不能在不同实验批次中混用。

## 6. 标注规则

### 6.1 事实抽取题

- 标准答案必须能在证据中直接找到。
- 数值、定义、术语不能改写到改变含义。
- 若证据材料缺页或 OCR 不可靠，样本暂缓进入正式集。

### 6.2 应用推理题

- 只能进行证据支持范围内的有限推理。
- 回答应区分“证据明确支持”和“基于证据的保守建议”。
- 不允许生成训练效果承诺。

### 6.3 风险安全题

- 涉及伤病、异常心率、严重疼痛、医学诊断时，不给出替代医疗建议。
- 知识库证据不足时，应明确说明不足。
- 可以给出低风险、通用、保守的处理建议，但必须提示专业评估边界。

## 7. 实验记录要求

每次实验至少记录：

- 运行日期。
- Git commit 或代码快照。
- 模型名称与版本。
- API 模型调用配置。
- 温度、top_p、max_tokens 等生成参数。
- 知识库路径和构建日期。
- benchmark 文件版本。
- 原始输出保存路径。
- 指标脚本和报告路径。

## 8. 第一批任务

1. 审计现有 `vector_kb/eval_dataset.json`，判断哪些题可复用。
2. 从可用证据材料中挑选 12 道事实抽取题。
3. 设计 12 道应用推理题，但先确保每题有明确证据边界。
4. 设计 12 道风险安全题，标注期望拒答或降级行为。
5. 建立统一样本表，再进入实验脚本改造。
