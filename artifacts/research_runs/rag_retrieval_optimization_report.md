# 马拉松助手 RAG 检索质量系统性分析与优化

> 给 Gemini 打分用。记录 5 天内的 6 轮优化实验、根因分析、和最终效果。

---

## 1. 问题定义

**目标**：马拉松训练 AI 教练的 FAISS 向量检索，用户问"减量期怎么安排跑量"时，能从知识库中精确召回对应的**那一段文字**（不是那一整篇论文）。

**初始状态**：
- 嵌入模型：nomic-embed-text (384 维，Ollama 本地部署)
- 索引：FAISS 平面索引，14,327 个片段
- 切分策略：固定窗口 chunk_size=500, overlap=50
- 评测集：66 条（56 正例 + 10 反例），6 项指标

---

## 2. 实验路线全览

```
实验1: 领域过滤 ──→ 实验2: 分库检索 ──→ 实验3: 页眉剥离
                                            │
                                    实验4: BM25 RRF 混合检索
                                            │
                                    实验5: Parent-Child 上下文
```

### 2.1 实验 1：领域过滤

**做法**：查询提取领域标签 → 过滤 FAISS 结果中标签不匹配的片段。

**结果**：
| 指标 | 无过滤 | 有过滤 |
|------|--------|--------|
| 精确召回@5 | 41.5% | 30.4% |
| 反例命中率 | 100% | 100% |

**发现**：94.6% 片段没有领域标签 → 过滤几乎无效 → 必须先做标签传播。

**后续修复**：实现 `_extract_file_domain_terms()` 从文档元数据传播标签，覆盖率 100%。

### 2.2 实验 2：分库检索

**做法**：每个领域一个独立 FAISS 索引。查询按领域标签路由到对应分库。

**结果**（标签传播后重测）：
| 指标 | 统一索引 | 分库索引 |
|------|----------|----------|
| 精确召回@5 | 30.4% | 30.4% |
| 同文档召回@5 | 55.4% | 57.1% |
| 训练方案精确 | 12.5% | 12.5% |

**发现**：分库对精确召回**零帮助**。训练方案 12.5% 没变 → 问题不在跨领域竞争，在同领域内片段向量坍缩。

**关键证据**：训练分库（5548 片段）内 top-20 分数从 0.659 到 0.638，带宽仅 **0.021**。nomic-embed-text 认为这 20 个片段几乎同等相关。

### 2.3 实验 3：页眉剥离

**做法**：检测并移除每页重复的论文标题/页码前缀（如"Effects of tapering... Page 5."），消除"标题污染"。

**统计**：95.1% 的片段（14,075/14,798）被清理。

**结果**：
| 指标 | 原始分库 | 清洗分库 |
|------|----------|----------|
| 精确召回@5 | 30.4% | 30.4% |
| 分数带宽 | 0.2594 | 0.2662 |

**发现**：修改了 95% 的文本，检索结果不变 → 问题不在数据质量，在**嵌入模型的语义分辨率**。

**网上验证**（JavaGuide RAG 优化万字长文）：
> "第一次做 RAG 时，很多人会陷入一个误区：疯狂换 embedding 模型，结果线上错误率没明显下降。60% 的问题根本不是向量相似度不够。"

### 2.4 实验 4：BM25 RRF 混合检索（P0）

**做法**：每路查询变体同时跑 FAISS（语义）和 BM25（关键词），用 RRF（Reciprocal Rank Fusion, k=60）融合两路排名。

**代码**：新增 `_rrf_fusion()` 函数（~25 行），修改 `retrieve()` 和 `_retrieve_sharded()`。

**结果**：
| 指标 | 分库（纯 FAISS） | 分库 + BM25 RRF | 变化 |
|------|-----------------|-----------------|------|
| 精确召回@5 | 30.4% | 32.1% | +1.7pp |
| 同文档召回@5 | 57.1% | 53.6% | -3.5pp |
| **训练方案精确** | **12.5%** | **31.2%** | **+18.7pp** |
| 营养精确 | 44.4% | 38.9% | -5.5pp |
| 伤病精确 | 30.8% | 23.1% | -7.7pp |
| 领域错配率 | 42.9% | 83.9% | 恶化 |

**核心发现**：训练方案精确召回 **暴涨 2.5 倍**。BM25 关键词匹配（"减量""间歇""配速"）补上了 FAISS 语义检索的盲区。但营养和伤病领域下降——这几个领域关键词倾向不同，需要调 RRF 参数或分领域调权。

**领域错配爆炸**：BM25 搜全库不分区 → 需加领域过滤。

### 2.5 实验 5：Parent-Child 上下文（P1）

**做法**：每个 500 字符"子片段"拼接 ±2 个相邻片段作为 "parent_text"（~2500 字符上下文窗口），存入 FAISS 元数据。检索命中子片段后，hit 自带完整上下文。

**结果**：结构已就绪，14798 个片段全部有 parent_text。效果需在 LLM 问答环节评测（检索指标无法衡量上下文质量）。

## 3. 根因分析（三层依赖链）

```
L1: 精确召回 30.4%，训练方案仅 12.5%
  └→ L2: 同领域内所有片段的向量几乎相同 —— 分数带宽 0.26，top-20 仅差 0.02
       └→ L3: nomic-embed-text 对马拉松领域训练文本的语义分辨率不足
            ├→ 模型训练语料以英文维基+网页为主，缺乏体育科学微调
            ├→ 384 维表征空间将"减量训练"和"间歇配速"都编码为"跑步训练相关内容"
            └→ 解法不是清洗数据，是引入另一个信号源（BM25 关键词）做互补
```

**为什么领域过滤/分库/页眉剥离都没用**：这三个操作都在消除**噪声**，但真正问题是**信号太弱**。噪声再少，如果信号本身的区分度不够（所有片段分数挤在一起），排序就是随机的。

**为什么 BM25 RRF 对训练方案有效**：训练方案的查询有强关键词信号——"减量""间歇""长距离""配速""乳酸阈"都在 BM25 索引中建立了明确的关键词-片段映射。BM25 看的是词频，不看语义，天然不坍缩。

## 6. 已知遗留问题

| 问题 | 严重度 | 计划 |
|------|--------|------|
| BM25 RRF 导致领域错配率从 42.9%→83.9% | 高 | BM25 搜索结果需加领域过滤 |
| 评测集 reference_chunk_id 未经人工验证 | 中 | 需 30 分钟人工确认 56 条 |
| BGE-M3 不可用（29+ 批 NaN） | 中 | 需文本预处理或放弃 |
| 反例命中率 100%（领域外查询无标签被放行） | 低 | 加无标签查询拒绝策略 |
| RRF k 参数未调优（当前 k=60） | 低 | grid search k ∈ [20, 40, 60, 80, 100] |
| nutrition/injury 在 BM25 RRF 后下降 | 中 | 分领域调 BM25 权重或 query expansion |

## 8. 结论

**核心洞察**：马拉松领域 RAG 检索的瓶颈不是数据噪声、不是跨领域竞争、不是嵌入模型选择。是 **384 维的语义向量对所有"跑步训练类"文本无法做细粒度区分**。这是 nomic-embed-text + 体育科学领域的先天局限。

**最优解**：**BM25 关键词信号 + FAISS 语义信号 → RRF 融合**。BM25 对"减量""间歇""配速"等术语天然敏感，恰好补上语义向量的盲区。训练方案精确召回从 12.5%→31.2% 验证了这条路径。

**不推荐继续做的事**：换嵌入模型（BGE-M3 NaN 不可用，multilingual-e5 未验证）、纯架构优化（分库、语义切分）——在确认嵌入模型区分度问题之前，这些方向的边际收益已耗尽。
